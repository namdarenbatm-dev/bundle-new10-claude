# Techno Bundle — نسخه ۱۰

سامانه طراحی مدل فروش محصولات کارتخوان توسن تکنو · طراحی مدل: مهدی نامدار

یک PWA کاملاً ایستا (HTML/CSS/JavaScript، بدون بک‌اند، بدون وابستگی زمان اجرا) برای طراحی باندل «کارتخوان نو + محصول محرک» (کش‌لس یا کارتخوان دست‌دوم). رابط فارسی و راست‌به‌چپ است و بعد از اولین بازدید آفلاین هم کار می‌کند.

## ساختار پروژه

```
index.html          صفحه اصلی (اسپلش ۵ ثانیه‌ای، صفحه‌های مدیر، باندل‌های تولیدشده، فرمول‌ها و کارگزار)
manifest.json       مانیفست PWA (مسیرها نسبی‌اند)
sw.js               Service Worker با کش نسخه‌دار
css/styles.css      استایل
js/core.js          منطق مالی خالص (عدد صحیح تومان) — مشترک بین مرورگر و تست
js/app.js           رابط کاربری
assets/             لوگو، فونت یکان، آیکون‌ها
tests/core.test.js  تست‌های خودکار منطق مالی (Node)
tests/core.fuzz.test.js  تست تصادفی (seed ثابت) در برابر یک مرجع مستقل BigInt
tests/e2e.js        تست اختیاری مرورگر (نیاز به Playwright)
scripts/check.js    بررسی ایستای ساخت (JSON، مسیرها، پیش‌کش SW، اندازه آیکون‌ها)
```

## اجرای محلی

Service Worker فقط روی `http://localhost` یا HTTPS کار می‌کند، پس برای آزمایش PWA:

```bash
python3 -m http.server 8080      # یا: npx serve .
# سپس http://localhost:8080 را باز کنید
```

بازکردن مستقیم `index.html` با `file://` هم برای کار با برنامه کافی است؛ فقط نصب PWA و حالت آفلاین (Service Worker) فعال نمی‌شود.

## تست و بررسی

```bash
npm test            # = منطق مالی + تست تصادفی   (نیازی به نصب بسته نیست)
npm run check       # = node scripts/check.js
npm run verify      # هر دو
```

نیاز: Node.js نسخه ۱۸ یا بالاتر.

## استقرار روی GitHub Pages

1. محتوای این پوشه را در ریشه‌ی یک مخزن GitHub (یا پوشه `/docs`) قرار دهید و commit/push کنید.
2. در GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**، شاخه `main` و پوشه `/ (root)` (یا `/docs`) را انتخاب کنید.
3. پس از چند دقیقه برنامه در `https://<user>.github.io/<repo>/` در دسترس است.

همه‌ی مسیرها (`manifest.json`، `sw.js`، پیش‌کش، ثبت Service Worker) نسبی‌اند، بنابراین زیرمسیر `/<repo>/` بدون تنظیم اضافه کار می‌کند. فایل `.nojekyll` لازم نیست چون هیچ پوشه‌ای با پیشوند `_` وجود ندارد.

### به‌روزرسانی نسخه

هر بار فایلی از لیست پیش‌کش تغییر کرد، مقدار `CACHE_VERSION` را در `sw.js` تغییر دهید (مثلاً `v10.0.4`). کاربران پیام «نسخه جدید برنامه آماده است» و یک دکمه‌ی پایدار «به‌روزرسانی برنامه» در نوار بالا می‌بینند؛ با زدن آن نسخه‌ی تازه فعال و صفحه یک‌بار بارگذاری می‌شود. در اولین نصب هیچ بارگذاری مجددی انجام نمی‌شود.

نام کش و کلیدهای `localStorage` شامل مسیر استقرار هستند؛ پس دو برنامه روی یک دامنه (مثلاً `user.github.io/app-a/` و `/app-b/`) داده و کش یکدیگر را نمی‌بینند و پاک نمی‌کنند.

## قواعد مالی

همه‌ی مبالغ عدد صحیح تومان‌اند (بدون اعشار و خطای گرد‌کردن).

1. سهم هر محصول محرک = قیمت فروش − بهای تمام‌شده − سود ثابت هر واحد
2. **قیمت کارتخوان نو در باندل = قیمت مصوب کارتخوان نو + بودجه بازاریابی کارتخوان آکبند** (کادر خودکار در داشبورد مدیر). بودجه بازاریابی فقط برای ساخت همین قیمت است، در پروژه‌ای جدا مصرف می‌شود، تخفیف نیست و از بودجه تخفیف کم نمی‌شود
3. بودجه تخفیف کارتخوان = تعداد محصول محرک × سهم هر واحد
4. تخفیف کل کارتخوان از بودجه تخفیف بیشتر نمی‌شود (تخفیف هر کارتخوان = کف عدد صحیح تقسیم بودجه بر تعداد کارتخوان، حداکثر تا «قیمت کارتخوان نو در باندل − کف رقابتی»)
5. قیمت نهایی کارتخوان در باندل (قیمت کارتخوان نو در باندل − تخفیف) هیچ‌گاه کمتر از کف رقابتی نیست
6. مبلغ کل = تعداد کارتخوان × قیمت باندلی کارتخوان + تعداد محصول محرک × قیمت فروش محصول محرک
7. بودجه بازاریابی هیچ کاربرد دیگری ندارد: نه تخفیف است، نه از بودجه تخفیف کسر می‌شود
8. باندل نامعتبر یا کم‌بودجه ساخته نمی‌شود (سهم محصول محرک منفی، کف بالاتر از قیمت کارتخوان نو در باندل، تعداد خارج از حد)
9. تعداد کارتخوان باید **از** تعداد محصول محرک بیشتر باشد؛ محصول محرک حداقل ۱ است
10. مضرب ۵ بودن تعداد لازم نیست

ورودی‌ای برای بهای تمام‌شده کارتخوان نو، سود کارتخوان نو یا سود کل باندل وجود ندارد (عمداً).

### سناریوی پذیرش (در تست‌ها)

| ورودی | مقدار |
|---|---|
| قیمت مصوب / کف | ۲۰٬۰۰۰٬۰۰۰ / ۱۵٬۰۰۰٬۰۰۰ |
| بازاریابی هر کارتخوان | ۱٬۰۰۰٬۰۰۰ |
| بها / فروش / سود ثابت محصول محرک | ۲۵٬۰۰۰٬۰۰۰ / ۴۲٬۰۰۰٬۰۰۰ / ۲٬۰۰۰٬۰۰۰ |
| تعداد | ۵ کارتخوان + ۲ محصول محرک |

نتیجه: سهم هر واحد ۱۵٬۰۰۰٬۰۰۰ · قیمت کارتخوان نو در باندل ۲۱٬۰۰۰٬۰۰۰ (۲۰٬۰۰۰٬۰۰۰ + ۱٬۰۰۰٬۰۰۰) · بودجه تخفیف ۳۰٬۰۰۰٬۰۰۰ · تخفیف هر کارتخوان ۶٬۰۰۰٬۰۰۰ · قیمت نهایی کارتخوان ۱۵٬۰۰۰٬۰۰۰ · مبلغ کل ۱۵۹٬۰۰۰٬۰۰۰ تومان.

## نمای مدیر

- تنظیمات (۹ ورودی + نوع محصول محرک) با اعتبارسنجی لحظه‌ای؛ اعداد فارسی و جداکننده‌ها پذیرفته می‌شوند.
- تولید همه‌ی باندل‌های معتبر در سقف تعداد تعریف‌شده.
- انتشار / لغو انتشار هر باندل؛ دکمه «جزئیات» کنار وضعیت انتشار، جزئیات را در مودال نشان می‌دهد.
- اولویت رتبه‌بندی با دکمه‌های بالا/پایین. پیش‌فرض: کارتخوان بیشتر ← قیمت کمتر ← محصول محرک کمتر ← مبلغ کل کمتر ← بودجه باقی‌مانده بیشتر.
- خروجی CSV (UTF-8 با BOM، مناسب Excel)، چاپ / ذخیره PDF، بازنشانی پیش‌فرض، پاک‌کردن داده‌ها (با تأیید).
- «لینک برای کارگزار»: لینکی می‌سازد که فقط باندل‌های منتشرشده، قیمت‌ها و سقف ارتقا را دارد.

اگر مقدار تنظیمات طوری تغییر کند که قیمت یک باندل منتشرشده عوض شود، آن باندل با قیمت جدید «منتشر نشده» است (کلید انتشار شامل قیمت‌هاست) و هشدار نمایش داده می‌شود.

## صفحه‌ها

- **مدیر**: تنظیمات مدل و اولویت‌ها.
- **باندل‌های تولیدشده**: جدول باندل‌ها با فیلتر و مرتب‌سازی شبیه Excel روی هر ستون (کلیک روی عنوان ستون: مرتب‌سازی صعودی/نزولی، جستجو و انتخاب مقدارها)، چیپ فیلترهای فعال، فیلتر «فقط منتشرشده‌ها»، آمار فهرست فیلترشده، انتشار/لغو انتشار، CSV و چاپ. «انتشار»، «لغو انتشار» و CSV هنگام فعال‌بودن فیلتر روی همان فهرست فیلترشده عمل می‌کنند. ستون «رتبه» همیشه رتبه بر پایه اولویت‌هاست و با مرتب‌سازی عوض نمی‌شود. فیلترها ذخیره نمی‌شوند.
- **فرمول‌ها**: همه فرمول‌های مدل به فارسی، با نمونه محاسبه با تنظیمات فعلی.
- **کارگزار**: پیشنهاد خودکار.

### قیمت واقعی کش‌لس در بسته (شاخص تحلیلی)

قیمت واقعی کش‌لس در بسته = قیمت مارک‌شده + ⌊ بودجه باقی‌مانده کل بسته ÷ تعداد کش‌لس بسته ⌋، که قیمت مارک‌شده = بهای تمام‌شده + سود ثابت هر واحد و بودجه باقی‌مانده = بودجه تخفیف − تخفیف تخصیص‌یافته به کارتخوان‌ها (فقط یک‌بار). سهم هر واحد برای ماندن در عدد صحیح تومان به پایین گرد می‌شود. این شاخص در جدول، جزئیات و CSV نمایش داده می‌شود و مبلغ کل، قیمت فروش کش‌لس، قیمت کارتخوان، انتشار، لینک و پیشنهاد کارگزار را تغییر نمی‌دهد. مثال آزمون: ۲۵٬۰۰۰٬۰۰۰ + ۲٬۰۰۰٬۰۰۰ = ۲۷٬۰۰۰٬۰۰۰؛ باقی‌مانده ۵٬۰۰۰٬۰۰۰ ÷ ۲ = ۲٬۵۰۰٬۰۰۰؛ نتیجه ۲۹٬۵۰۰٬۰۰۰ تومان.

## نمای کارگزار

- فقط باندل‌های منتشرشده؛ کارگزار بودجه‌اش را وارد می‌کند.
- یک «پیشنهاد اصلی» خودکار: بیشترین تعداد کارتخوان در حد بودجه، سپس کمترین قیمت هر کارتخوان.
- حداکثر یک «ارتقای پیشنهادی» که واقعاً بهتر است: کارتخوان بیشتر، یا هم‌تعداد با قیمت کمتر **بدون** اینکه تعداد محصول محرک از پیشنهاد اصلی بیشتر شود. «پرداخت اضافه» = مبلغ باندل ارتقا − بودجه کارگزار و هرگز از سقف تعریف‌شده بیشتر نمی‌شود؛ اختلاف با پیشنهاد اصلی هم نمایش داده می‌شود.
- فهرست بلند برای انتخاب نمایش داده نمی‌شود.
- دکمه «پاکسازی داده‌ها» (با تأیید) **فقط صفحه کارگزار** را پاک می‌کند: بودجه واردشده و پیشنهاد دریافتی. تنظیمات، قیمت‌ها، اولویت‌ها و وضعیت انتشار در صفحه مدیریت هیچ تغییری نمی‌کند. (پاک‌کردن کامل داده‌ها فقط با دکمه «پاک‌کردن همه داده‌ها» در صفحه مدیر است.)

## داده‌ها، حریم خصوصی و محدودیت‌ها

- بدون بک‌اند و بدون ردیاب: تنظیمات و وضعیت انتشار در `localStorage` همین مرورگر ذخیره می‌شود.
- چون سرور وجود ندارد، مدیر و کارگزار روی دستگاه‌های جدا داده‌ی مشترک ندارند. راه انتقال، «لینک برای کارگزار» است. این لینک بهای تمام‌شده، سود، کف رقابتی و بودجه بازاریابی را **ندارد**؛ کارگزار مبالغ کل را خودش از قیمت‌های واحد دوباره محاسبه می‌کند.
- جداسازی مدیر/کارگزار فقط جداسازی رابط کاربری است، نه امنیت: این یک برنامه‌ی سمت مرورگر است و هر چه در مرورگر باشد قابل مشاهده است. مقادیر واقعی بهای تمام‌شده را در کد ننویسید؛ مقادیر پیش‌فرض داخل `js/core.js` فقط نمونه‌اند.
- سقف‌ها: حداکثر ۱۰۰ برای تعداد کارتخوان و ۱۰۰ برای محصول محرک، و حداکثر ۱٬۰۰۰٬۰۰۰٬۰۰۰٬۰۰۰ تومان برای هر مبلغ.
- در پیکربندی‌های بزرگ (مثلاً ۱۰۰×۱۰۰ = ۴٬۹۵۰ باندل) جدول هر بار ۲۰۰ ردیف نشان می‌دهد و دکمه «نمایش بعدی» دارد؛ همه‌ی باندل‌ها ساخته، منتشر، در CSV و در چاپ آورده می‌شوند. لینک کارگزار هم بلندتر از ۸٬۰۰۰ نویسه هشدار می‌دهد.
- لینک کارگزار تاریخ صدور دارد و در نمای کارگزار نمایش داده می‌شود؛ لینک امضا یا رمز ندارد و قابل دست‌کاری است (محدودیت طبیعی برنامه‌ی بدون بک‌اند).
